# Configuration
Services read process env; systemd loads `~/tools/tools.env`, protected `~/.config/agent-secrets/{credentials,azure-foundry,azure-openai-transcription}.env`, then product env files (later wins). No file may override `PYTHONPATH`.
## Files
- `config/{gateway-ms,gateway-rss,rss-audio,meeting-summary,tts}.env.example` → protected `~/.config/tg-tools/<product>.env` (0600). See [operations](telegram-tools-operations.md) for unit/file mapping.
- Transcription additionally loads `~/.config/agent-secrets/azure-openai-transcription.env`, then `~/.config/tg-tools/rss-audio.env`; existing env wins.
- `TTS_PI_ROLES_FILE`: optional JSON role map. `models` maps tier names to `provider,model`; `write,review,transcript_topics,transcript_mentions` override `tier,provider,model,thinking,flags,system_prompt`. Example: `{"write":{"tier":"sol","thinking":"high"}}`.
- Provider OAuth files: `MEETING_SUMMARY_PI_AUTH_PATH` (default `~/.pi/agent/auth.json`), Pi's agent directory/auth and Claude's subscription login. Never commit auth files.
- `services/*.json` are product route manifests: `service,botIdentity,ownerSystem,routes`; each route defines `routeId,routeKind,workloadType,ownerSystem,chatIdBinding,threadMode,threadIdBinding,rules`. See `tg-gateway/tg_gateway` for parsing.
## Environment keys by purpose
Suffixes: `*_URL/ENDPOINT` are URLs, `*_DIR/PATH/FILE/ROOT` filesystem paths, `*_BIN` executable paths/names, `*_TOKEN/KEY/SECRET/HASH` credentials, `*_KEY_CMD` shell key retrieval commands.
`*_ID` identifies a resource; profiles/workload types/queues/users are comma-separated lists. `*_SEC/SECONDS/TIMEOUT_S` are seconds, `*_BYTES/CHARS/TOKENS` are limits. `ENABLED/REQUIRED/MOCK` are flags. Exact defaults and validation live in each product's settings module.

## Required publication settings and examples
- Required (blank is an error): `RSS_AUDIO_BASE_URL=https://rss.example.test`, `RSS_AUDIO_B2_BUCKET=example-audio`, `TTS_B2_BUCKET=example-audio`, `TTS_FEED_URL=https://rss.example.test/tts/podcast.xml`.
- Also required (missing/blank is an error): `TTS_FEED_TITLE` (success label, e.g. `Example TTS`), `TTS_AZURE_TTS_BASE_URL` (speech endpoint, e.g. `https://speech.example.test`), `TTS_AZURE_CHAT_BASE_URL` (title endpoint, e.g. `https://chat.example.test/openai/v1`), `TTS_AZURE_TTS_KEY_CMD`, `TTS_AZURE_CHAT_KEY_CMD` (key retrieval commands; synthetic resource examples in `config/tts.env.example`). No account-scoped defaults remain.
- Routes require explicit `RSS_AUDIO_MULLVAD_PROXY=http://127.0.0.1:8888`, `RSS_AUDIO_MAC_SSH=user@example.test`, `RSS_AUDIO_MAC_YTDLP_PATH=/path/to/yt-dlp`.
- `TG_GATEWAY_BOT_TOKEN_ENV` names the credential env key (e.g. `EXAMPLE_BOT_TOKEN`); no bot token is stored in manifests.
- `TG_GATEWAY_ROUTE_BINDINGS_JSON={"tts_chat_id":-1000000000001,"tts_thread_id":101}` maps logical route bindings to Telegram topic IDs; production also requires allowed chat/users and systemd.
- `TG_TOOLS_WORKSPACE_NAME=workspace` allows artifacts under an ancestor with that basename (default: `workbench`); outside it only the workdir is allowed.
- Paths in templates are placeholders: use absolute deployment paths; systemd EnvironmentFile does not expand `~`.
- Standard process settings (`HOME,PATH,USER,LANG,LC_*,TMPDIR,XDG_*`), HTTP proxy/TLS variables and systemd invocation markers control host behavior; the subprocess allowlist is in `shared/tg_tools_common/runtime_policy.py`. Most model subprocesses strip provider secrets by design.
- Tooling configuration: `pyproject.toml` owns dependency pins; generated requirements/lock own hashes; `TG_TOOLS_PYTHON` selects the validator interpreter (otherwise `sys.executable`). See [dependencies](dependencies.md).
